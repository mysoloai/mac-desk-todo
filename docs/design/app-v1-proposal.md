# app-v1 · 浮窗待办实现方案

## 背景

用户需要一个 macOS 菜单栏常驻的快速便签待办：⌥⌘N 呼出、置顶、可拖拽、可调透明度，编辑即时保存，外观可配色与配字号。要求每个条目有一点“手账感”的完成交互（空心圆 → 实心对钩）。

## 目标

- 零干扰：不入 Dock，仅菜单栏；关闭即最小化回菜单栏。
- 快：呼出到可输入 < 1 次交互；点击空白即可新建。
- 可控外观：10 个预设底色 + 圆盘自选；字号 12–30 实时预览。
- 可维护：脚本化构建、自检、回归，不依赖 Xcode 工程。

## 非目标

v1 明确的非目标：不做同步、账号、提醒、重复任务。

## 方案对比

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| A. AppKit 自绘 + NSPanel（采纳） | 完全控制圆圈/时间戳/悬停浮层像素细节；启动毫秒级；单文件可执行直出 .app | 需手写命中测试与行高测量 | 采纳 |
| B. SwiftUI + MenuBarExtra | 代码短 | 自定义 hover 浮层与行内编辑器受布局系统约束，细节难对齐 | 放弃 |
| C. Electron / Tauri | 跨平台 | 体积大、常驻内存高、与“轻量便签”定位冲突 | 放弃 |

## 关键决策

1. 列表自绘（`TodoCanvasView`），编辑时叠一个透明 `NSTextView`——保证折行与光标行为是系统原生。
2. 顶部浮层与滚动区分离：浮层单独一层 `ChromeOverlayView`，列表滚动区整体下移 `topInset`，避免滚动内容穿透顶栏。
3. 数据用单 JSON 文件 + 0.18s 合并写，退出/结束编辑强制 flush；无数据库依赖。
4. 设置用独立窗口，改动实时广播（`AppSettings.didChange`），浮窗即时重绘。

## 风险

- 系统深色模式下控件外观需固定为 aqua，靠底色亮度自动切文字颜色，避免“深底黑字”。
- 无 Xcode 工程的 ad-hoc 签名包在覆盖安装时可能被 taskgated 杀掉，改为整包替换（见 lessons）。
